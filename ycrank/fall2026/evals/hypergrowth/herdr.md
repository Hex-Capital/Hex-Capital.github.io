# herdr -- Hypergrowth Evaluation

**Action:** Watch  
**Evidence confidence:** Low

### Company case

**Product-led adoption** is the strongest path. The likely first buyer is a developer who regularly runs several long-lived coding agents across machines. Herdr’s documented workflow keeps sessions alive through client disconnects and surfaces agents waiting for input. The same job should travel across markets where developers can run the host software and connect over SSH. The memo establishes a portable workflow. Paid adoption across markets remains unverified. (The Idea)

GitHub, command-line installers, and app stores give developers a self-serve route to the product. Mobile app ratings and a community mod for relaunching processes provide limited evidence of hands-on use. Herdr’s reported cumulative installs are for the original TUI, whose sessions are unavailable in the separate desktop and mobile runtime. The memo does not trace an independent cohort from discovery to first value on that runtime. (The Idea, Market & Traction, Key Risks)

The first unproven link is conversion from free use to paid connectivity. **Scenario assumption:** Developers who already depend on Herdr across several hosts pay for Herdr Cloud to simplify connecting those machines. Herdr announced a waitlist with no disclosed price. The memo supplies no concrete buyer commitment, account-level repeat use or expansion, or measured marginal delivery costs. Running agents on users’ own hosts could limit Herdr’s compute burden, while Cloud infrastructure and support costs remain unknown. (The Idea, Key Facts)

### Countercase

Developers may get enough value from free SSH access or, for single-provider users, from their agent provider’s own app. The separate runtimes also mean the original TUI’s audience has to adopt a new runtime to use the desktop and mobile clients with its sessions. That weakens the case that existing distribution will produce paying Cloud users. The structural downside gate does not apply because paid conversion through a self-serve rollout remains testable. (The Idea, Market & Traction, Key Risks)

### Decisive diligence question

Can independent developers already supervising agents across several hosts activate and pay for Herdr Cloud without founder-led setup, then keep using it over several normal work cycles? Account records showing that pattern across several users would move the action to Reach out. If the rollout shows those users consistently return to free SSH because paid connectivity adds too little value, move to Pass.
