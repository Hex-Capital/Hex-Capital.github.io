# GitCafe -- Vinod Khosla Evaluation

The consequence case is too small as presented. GitCafe proposes a modern replacement for GitHub inside a version-control market estimated at $1.24 billion in 2025. It does not quantify an expert bottleneck eliminated, a societal resource curve changed, or even a 10x reduction in software-development cost. More public commits and more leaked secrets create demand, but demand is not consequence. This currently looks like a better forge, not an option on a radically different world.

The strongest evidence is technical. A two-person team has built a custom libgitz engine, kiln runtime, native `cafe:git` binding, forge, CLI, and native stacked diffs. That is real work, not an API wrapper. But vertical integration is only valuable if it breaks an incumbent constraint. GitCafe supplies no measured comparison showing that its stack makes agent operations, repository performance, review cycles, or security 5–10x better than GitHub, GitLab, or Bitbucket. Owning every layer without proving a discontinuity can become an expensive way to reproduce existing infrastructure.

The bull case stings: engineers at eight named organizations are already using a beta built by two people, while GitHub exceeds $3 billion ARR and GitLab exceeds $1 billion ARR. A small, technically aggressive team can enter through stacked diffs and agent skills, then expand into a platform. That is the relevant exception pattern. But the dossier shows neither repeat usage nor a learning loop, and the cited market is not yet large enough to compensate for attacking GitHub’s 180 million developers and 630 million repositories head-on. Incumbent scale is evidence of demand; it is not evidence that GitCafe has found the lever that displaces it.

Capital allocation is also backwards or, at best, undocumented. The existential risk is migration and workflow replacement: GitHub Actions support, GitLab CI support, and one-command migration remain planned. Yet there is no cheapest decisive experiment, adoption threshold, budget, or stop condition for proving that teams will move private source code onto a beta service with no SLA. Building more forge surface area before measuring sustained repository migration removes little of the largest risk.

Veronica C. has credible founder-market alignment through Rust, TypeScript, platform bindings, and prior work as a founding engineer at Corgi. What is missing is the evidence I care about more than résumé fit: a material belief revised after user data or a complementary recruit brought in to own migration, reliability, security, or enterprise adoption. Pricing provides no economic evidence either. Private repositories are free, paid terms are unpublished, and there is no bottom-up model connecting infrastructure cost, support burden, and willingness to pay.

My 36-month forecast is that GitCafe pivots from a general GitHub replacement into an agent-native stacked-diff and code-review layer while remaining below $1 million ARR. I pass today. The single flip condition is a paid cohort of at least 20 teams that moves most pull-request activity to GitCafe for 90 days while demonstrating a measured 5x improvement in agent-plus-human review cycle time versus GitHub. That would convert impressive implementation into a technical discontinuity with migration evidence.
