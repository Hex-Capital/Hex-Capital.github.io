# Speko -- Naval Ravikant Evaluation

Speko routes 56 providers and 159 models through one API, so Speko is a domain-insider builder tool with strong specific knowledge but almost no network compounding. Beknazar Abdikamalov spent four years selecting voice stacks and previously built voice products as Hupo’s CTO. That is founder-product-market fit. But Speko remains a tollbooth, not a network: each new developer receives roughly the same utility whether ten or ten thousand developers arrived before them. Specific knowledge creates the product; absent network effects cap the upper-bound geometry.

Stack Overflow is the high rung because practicing developers converted lived frustration into infrastructure for other developers. Speko shares that load-bearing mechanism: Abdikamalov endured repeated voice-model bake-offs, then encoded the work into benchmarks, SDKs, adapters, and automatic failover. Speko diverges where Stack Overflow already had public technical artifacts and user-added knowledge compounding; Speko’s TypeScript and Python repositories have only two stars each, with no public personal repositories from Abdikamalov. The specific knowledge looks real, but its public proof and community pull remain early. I score the founder well above a credential-driven “ex-Amazon identified a market” profile, but below the Stack Overflow rung.

Anchorage Digital’s low-rung mechanism on network value is permissioned, single-sided infrastructure: additional customers do not automatically improve custody for prior customers. Speko shows the same weakness without Anchorage’s regulatory moat. Speko’s public benchmarks may eventually learn from provider failures, but the dossier identifies neither a proprietary dataset nor a demonstrated routing advantage. Seven benchmark boards are useful content, not yet a network. Speko can serve one customer independently of every other customer, so the 90 weekly MCP downloads and 85 weekly SDK downloads create adoption, not compounding user-added value.

Speko’s $100 signup credit, self-service API key, Python and TypeScript SDKs, hosted MCP server, and provider-cost-plus-5% pricing make code the primary leverage. Over 18 months, Speko can integrate a provider once and replicate access across every developer at near-zero marginal distribution cost; public benchmarks can become media leverage that attracts searches, comparisons, and integrations. The failure mode is that Speko’s code leverage compounds someone else’s models while LiveKit or Vapi copies the routing layer. Permissionless distribution is present. Permissionless defensibility is not.

Speko addresses a voice-agent market forecast to grow from $2.54 billion in 2025 to $35.24 billion by 2033, with adjacent pivot room into workload-specific evaluation, observability, inference procurement, and real-time reliability infrastructure. Speko would move into the top market rung if its benchmark engine generalized beyond voice into a neutral routing control plane for multimodal inference. Speko would fall a tier if the 5% routing fee remains attached only to voice-provider arbitrage, because a narrow aggregation layer can be compressed by providers and bundled by LiveKit, Vapi, or Bland AI.

Twitter’s early founder evidence offers the clean single-anchor comparison for the 10-year-partner test: Jack Dorsey shipped and Ev Williams had completed Blogger cleanly before the check. Speko shows intelligence and energy through Abdikamalov’s UNIST computer-science degrees, Amazon engineering work, prior Hupo CTO role, and four years inside the problem. Speko provides no public evidence about how Abdikamalov treated prior partners, why Hupo ended, or how the four-person organization is governed. Integrity is not inferred from credentials. Silence receives the neutral default, because long-term games require evidence of long-term people.

LiveKit is the most likely endpoint: by July 2029, Speko will reach $1 million–$3 million in ARR and be acquired by LiveKit for under $50 million to fold benchmark-driven routing into LiveKit Cloud. Speko’s founder knowledge can build a valuable measurement layer, while Speko’s weak network effects make independent category dominance less likely than strategic absorption. The same abstraction that helps developers switch providers also makes Speko legible to the larger platform already controlling real-time application infrastructure.

Speko’s combined 175 weekly package downloads and four GitHub stars support the strongest bear case: LiveKit can reproduce routing, Vapi already supports provider swapping, public benchmarks may not transfer to customer workloads, and Speko owns neither the models nor the transport layer. That bear case stings because builder tools without community pull become features. Speko survives it for now because 56 provider integrations, 159 measured models, seven dated boards, and Abdikamalov’s four years of lived workflow pain constitute more than a pitch-deck abstraction. I write a small angel check on specific knowledge and code leverage, not on the current moat. I flip to Pass if Speko has not exceeded 1,000 combined weekly SDK and MCP downloads by July 2027; failure to compound permissionless adoption would show that the architecture is technically open but economically inert.
