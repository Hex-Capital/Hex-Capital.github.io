# Archal -- Paul Graham Evaluation

The first question is what broke and what the founders did about it. The dossier never answers it. Archal has built something substantial—22 independently implemented, stateful service environments with REST and MCP endpoints, mutation recording, reset behavior, and an npm CLI—but there is no named obstacle followed by a dated workaround. The artifact proves that Aidan Tiruvan and Noah Song can ship. It does not yet prove they are relentlessly resourceful when reality refuses to cooperate.

The product is the strongest part of the case. Simulating GitHub, Slack, Stripe, and other mutable services is harder than wrapping their live APIs, and the usage-based price of $0.10 per environment-minute makes the infrastructure immediately consumable. This resembles my unstated preference for programmable primitives assembled before their category is settled. The 22 environments are a concrete pre-round substrate, not a diagram. But Archal publishes no fidelity benchmark, external validation, or evidence that developers have incorporated these environments into daily testing. It has built the well before showing that anyone is thirsty.

The missing demand evidence matters more than the 687 LinkedIn followers. There is no named developer niche, paid usage, repeat session, retained CI integration, or customer demanding an unplanned workflow. Self-service signup, $20 credits, and founder calls are sensible acquisition machinery, but machinery is not pull. The narrow-well question is precise here: which agent team repeatedly breaks shared test accounts badly enough to pay by the minute for Archal? The dossier supplies the generic user categories but no observed answer.

There may have been a useful route change. YC describes automatic verification and fix PRs, while the current site sells sandbox infrastructure and leaves evaluation to customers. That could be a running-back move from application to primitive. It could equally be unresolved positioning. Without the customer or technical observation that caused the change, I assign no credit beyond the default for adaptability. The discrepancy over whether Noah remains a cofounder also needs an ordinary factual explanation; a two-person company cannot treat its founder roster as a cosmetic detail.

The bull case is that Tiruvan encountered agent failure modes while red-teaming at Scale AI, then the team did the ugly work of recreating 22 external services before asking permission. Enterprise security reviews, private deployments, API drift, and state fidelity are genuine schleps. If agent developers adopt Archal as the repeatable test layer beneath evaluation systems, those accumulated edge cases could become difficult to copy. This is the strongest case for an exception to the failed resourcefulness gate. It still falls short because the known exceptions require unmistakable user pull or independently validated proof, and Archal has disclosed neither.

The bear case is sharper: OpenAI’s Agents SDK already supports seven sandbox providers, while E2B and Runloop can extend toward simulated services from established execution infrastructure. Archal could become a feature between better-distributed platforms unless its environments are materially more faithful and developers return to them. I would not write the check today. The single flip condition is verifiable: show ten agent teams running Archal in recurring CI for four consecutive weeks, with at least three paying and one documented case where a simulation caught a production-relevant failure. That would establish the user pull and expose the founders’ behavior under real integration pressure.
