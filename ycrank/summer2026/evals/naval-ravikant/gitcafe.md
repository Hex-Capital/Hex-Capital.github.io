# GitCafe -- Naval Ravikant Evaluation

Veronica has built enough to make the founder signal real. A former founding engineer at Corgi, she has 72 public repositories and documented TypeScript, Rust, and platform-binding work. More importantly, GitCafe owns a working stack from libgitz through the kiln runtime, native binding, forge, and CLI. This is specific knowledge expressed through artifacts, not credentials. The missing evidence is whether she previously operated or sold a repository product at scale; technical proximity is strong, exact commercial experience is not yet proven.

The custom stack is also the most impressive and most misleading part of the investment case. Reimplementing git proves depth, but code is not durable merely because it was difficult to write. If GitHub copied the terminal workflow, stacked diffs, and agent-skill installation, GitCafe has no demonstrated proprietary data, hardware, model, rights, or customer-created network left behind. Repository history may eventually create switching costs, but migration itself is still planned. A moat described in the future tense is a roadmap.

The bull case is sharper than “another GitHub.” Engineers at eight named organizations already use the beta, suggesting that a small team has found a real dissatisfaction with browser-centered development. Native agent workflows could become a new repository control plane as public commits rise and AI-assisted code increases secret exposure. Owning the engine through the forge might let GitCafe shape that control plane faster than incumbents carrying legacy abstractions. If repeated deployment generates proprietary security or agent-performance data, the technical stack becomes an accumulating asset rather than expensive code.

The present evidence does not establish that loop. GitHub already has more than 180 million developers and 630 million repositories; GitLab has crossed $1 billion in ARR. GitCafe’s Actions compatibility, GitLab CI support, and one-command migration remain unshipped, so the product asks customers to abandon a network before supplying workflow parity. The reported $1.24 billion version-control market is a top-down category estimate, not a causal path from the initial terminal-first wedge into a larger adjacent market.

The economics are similarly unresolved. Private repositories are free during beta, pricing is unpublished, and none of the eight organizations is identified as a payer. Free usage can be sufficient when users are already making the system more valuable for one another. Here there is no contribution, referral, liquidity, or collaboration-density evidence showing that the ninth organization benefits because the first eight joined. GitCafe resembles a hosted tool whose labor and infrastructure scale with customers, not yet a permissionless system that compounds while the company sleeps.

I find no disclosed integrity, artificial-deadline, or founder-dependence red flag. The problem is structural rather than personal. The known exceptions for missing monetization require an observable network or an unusually differentiated product language; neither is yet demonstrated. My 36-month base case is that GitCafe remains below $1 million ARR unless it pivots from general-purpose forge replacement into an agent-native repository security and execution layer. I would reopen the decision upon one verifiable condition: ten paying teams showing that proprietary deployment data measurably improves agent review or secret detection across customers.
