# Nebula Security -- Elad Gil Evaluation

The market map is straightforward: AI-assisted development is increasing code-review volume, frontier models can now discover vulnerabilities autonomously, and software companies will buy continuous repository security if validated findings convert into trusted, deployable fixes. Nebula Security’s controlling variable is therefore not vulnerabilities found. It is the percentage of findings that engineering teams accept and remediate without human security triage. The dossier establishes exploit reproduction as the mechanism, but provides no acceptance-rate threshold or customer evidence proving it.

The technical proof is unusually strong for pre-seed. Vega reports 1,393 validated findings, 98 public CVEs, eight Chrome zero-days, and 1,356 Linux-kernel bugs. The team has also earned more than $400,000 in bug bounties. These are substantially more informative than an AI-security demo because they demonstrate that the system and researchers can produce externally verifiable security results. Yet they validate vulnerability discovery, not the commercial variable. A security team may admire the research while declining to send sensitive repositories, tolerate automated patches, or pay continuously.

The technology shift is real but the market is already crystallizing. Application security was a $10.65 billion market in 2025, and model capabilities are making continuous analysis feasible while AI-generated code expands review volume. However, OpenAI Codex Security and Microsoft MDASH are entering from platforms that already control developer distribution. RunSybil, XBOW, and Depthfirst have raised $40 million, more than $270 million, and $120 million respectively. Nebula has not shown a cost, speed, margin, or accuracy advantage sufficient to explain why this becomes an independent large company rather than a feature inside an existing development or security platform.

Vega has the beginnings of an owned workflow: it monitors code changes, diagnoses root causes, reproduces exploits, generates patches, and supplements automation with human researchers. Stronger models should improve those tasks. That is materially better than formatting scanner output. Durability depends on Nebula retaining repository context, remediation outcomes, permissions, and CI/CD integration; none of those feedback loops is yet documented at customer scale. The inferred proprietary dataset is not a moat until the founders can quantify what a well-funded competitor would spend—and how long it would take—to reproduce it.

The strongest bull case is the rare-technical-team exception. A cybersecurity PhD, Microsoft security experience, Black Hat work, DEF CON finalists, kernel and browser exploitation, and a 1.3K-star public exploit repository constitute scarce technical supply. The team has also launched an enterprise private beta after testing with YC companies. But the exception is incomplete: this is a crowded application layer, not a frontier research layer with an obvious capital bottleneck. There is no named paying customer, repeat production usage, retention, or revenue. GitHub attention and public CVEs demonstrate technical pull, not product-market pull.

I would monitor rather than invest today. My 36-month base case is that Microsoft acquires Nebula for its exploit-research team and validation assets before the company exceeds $5 million ARR; the workflow is promising, but distribution may consolidate faster than Nebula’s customer base forms. The single flip condition is a cohort of at least three named enterprises each paying over $100,000 annually after six months of continuous repository scanning, with more than half of Vega’s validated findings accepted for remediation. That would prove the controlling variable and change this from exceptional security research into a potentially durable company.
