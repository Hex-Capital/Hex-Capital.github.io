# Lyon -- Hypergrowth Evaluation

**Action:** Watch  
**Evidence confidence:** Low

### Company case

**Path B — Repeatable sales or partner distribution with account expansion.** The clearest first buyer is a fintech underwriting team that repeatedly uses transaction histories to predict default. Lyon’s direct-sales setup includes an intro booking page and a security questionnaire. Lyon reports a 112% relative improvement in default-prediction PR-AUC over one unnamed fintech’s existing tree-based model. That benchmark gives an underwriting buyer a specific reason to test the product. Buyer budget, production use, and conversion through the advertised sales route remain unverified. (The Idea, Market & Traction, Key Facts)

**Scaling scenario.** If that lift holds in production, Lyon could sell the same underwriting deployment to other fintechs and use the customer’s trained model to add paid fraud or cross-sell workloads. Lyon separately reported a premium-card conversion benchmark, but the memo leaves open whether it came from the same customer or led to a paid second workload. In a second geography, the same buyer and job could recur. The customer-cloud architecture could carry over, while Lyon would still have to map the institution’s event data and meet applicable validation and monitoring requirements. The memo contains no cross-market customer test. (The Idea, Defensibility, Market & Traction, Key Risks)

The contribution test is whether revenue from the next institution covers the added sales, security review, data integration, training, validation, and support. Within an account, a paid adapter could improve contribution if it reuses the existing model and the added revenue exceeds task-specific validation, inference, and support costs. Who pays for compute and how much Lyon staff time each rollout requires remain unknown. The growth mechanism is plausible, with low confidence in its repeatability. (The Idea, Defensibility, Key Risks, Key Facts)

### Countercase

Lyon could become a custom model-development vendor. Training starts from scratch for every institution, validation can add deployment work, and the memo describes a financial institution building a comparable system in-house. Even a strong benchmark could be hard to monetize if each buyer requires substantial engineering and can use the same tooling internally. The structural Pass gate remains unmet because the memo has no measured rollout costs or staffing data showing that Lyon’s effort scales proportionally with volume. (The Idea, Defensibility, Key Risks)
