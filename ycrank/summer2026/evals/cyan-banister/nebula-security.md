# Nebula Security -- Cyan Banister Evaluation

Move the clock to 2032: software is written continuously by machines, and every change meets an autonomous adversary before it reaches production. The necessary transitions are better vulnerability discovery, reproducible exploitation, trusted repository access, automatic remediation, and a feedback loop that improves with every scan. Nebula Security has one convincing leak from that world: Vega reports 1,393 validated findings, 98 public CVEs, and eight Chrome zero-days. The little object on the table is not the $10.65 billion TAM; it is the 1.3K-star exploit repository. But the dossier does not yet show that Nebula owns the journey from this artifact to the 2032 security layer. It describes the first technical step, not the complete causal chain.

The founders are the strongest part of the bet. Eten Zou’s security PhD, Microsoft work, and kernel research; Yuan Tan’s program-analysis work and Black Hat record; and Xiaochuan Yu’s and Frank Wu’s DEF CON and exploit-development histories all predate the company. The team has earned more than $400,000 in Google bug bounties, coauthored systems research, and produced public tools with hundreds of GitHub stars. This is not four people who noticed an AI-security funding wave last Tuesday. They have paid real technical tuition. What remains unproven is the Biz portion: who turns extraordinary research ability into distribution, pricing power, and an organization with one accountable decision-maker.

The system economics are much fuzzier. Static scanners produce noise, penetration tests are periodic, and manual audits consume scarce researcher time, but the dossier never quantifies the resulting delay or identifies a rule or gatekeeper capturing an artificial rent. Metered access and fixed-price audits could lower costs, yet no published prices, revenue, or customer workflow shows whose budget or agency actually changes. Nebula might return control to developers by placing verified fixes inside every code change. It might also become another security vendor selling an additional mandatory check. Those are materially different businesses.

The sharp bull case is that technical behavior this strange should outweigh missing pre-seed revenue. Ninety-eight public CVEs, eight Chrome zero-days, 364 repository forks, and an enterprise private beta are much stronger than a rendering or an LOI. A team that can repeatedly make real systems confess their flaws may discover the product surface after the research engine already works. I take that exception seriously. But the current evidence measures vulnerabilities found and researchers impressed, not customers repeatedly entrusting repositories, paying for continuous scans, or accepting patches. The working artifact is proven; the costly user ritual is not.

Vulnerability validation could become an enabling layer beneath machine-generated software, and reproduction before reporting is more valuable than another pile of model-generated warnings. Yet OpenAI Codex Security, Microsoft MDASH, RunSybil, XBOW, Depthfirst, and Hacktron are converging on the same bottleneck. Nebula has not demonstrated exclusive data, a controlled model, privileged distribution, or a scarce infrastructure asset that those companies must use. Its private beta may start a proprietary remediation loop, but a possible future moat earns no present credit. Right now this looks more like exceptional offensive-security talent inside a consensus wave than ownership of the layer beneath it.

The repository-custody question is my hardest gate. Customers must expose sensitive source code, while Nebula’s terms permit submitted content to be used and modified to provide, secure, and improve the service; the dossier identifies no explicit retention boundary, isolation model, or consent architecture. Four cofounders have clear operating titles, but control and contractual tiebreakers are undisclosed. I do not treat missing governance information as misconduct, but I will not write a personal check while both custody and accountability remain unanswered. I am neutral today. One verifiable condition flips me: ten unaffiliated production customers continuously scanning private repositories for six months, with paid renewals and a published architecture proving customer code is isolated, retention-limited, and excluded from cross-customer training.
