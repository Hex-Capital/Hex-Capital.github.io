# Caveman -- Hypergrowth Evaluation

**Action:** Watch  
**Evidence confidence:** Low

### Company case

Caveman’s strongest path is to convert developers who discover its free CLI on GitHub or npm into recurring buyers of Code credits. Assuming strong product-market fit, controlling the cost of repeated coding-agent sessions is a portable job. Code supports Claude Agent, Codex, and Cursor in a Mac or browser app, so developers can use substantially the same product across markets where they have access to those agents. The original repository’s roughly 121,000 stars establish a discovery channel. The memo documents self-serve signup and free use with existing keys or logins, while independent purchase and paid activation remain unverified. (*The Idea, Defensibility, Market & Traction*)

Code’s $20–$200 monthly credit tiers give retained developers a way to spend more if heavier workloads push them to higher plans. The company reports 21% lower list-price cost per solved task than Codex in a test where both solved 90 of 192 runs. In a paid-credit scenario where Caveman bears the model bill, contribution is the plan fee less the inference, hosting, and support attributable to that user. Context selection could lower inference cost if the benchmark transfers to paid workloads and the savings accrue to Caveman. Supplier costs and credit consumption are unverified, so the direction of contribution on typical workloads remains uncertain. Code launched in November with a listed team of one. The memo gives no realized revenue, paying-customer counts, or billable usage for Code, so initial traction uses the absent-evidence default. (*The Idea, Market & Traction, Key Risks, Key Facts*)

### Countercase

Developers who already have agent credentials can keep using Code for free. The original project’s audience could therefore generate substantial usage with little recurring credit revenue. An independent test of the original skill found that fewer output tokens still coincided with a higher bill after one run crossed a long-context pricing tier. That result raises a workload-specific risk for the savings proposition. The structural downside gate clears because the memo shows a portable product and a self-serve start, with no documented requirement for bespoke rollout or ongoing subsidies. Paid conversion and contribution remain the decisive gaps. (*The Idea, Market & Traction, Key Risks*)

### Decisive diligence question

Can a cohort of developers arriving from GitHub or npm buy Code credits without founder help and renew the following month at positive incremental contribution? Cohort records showing independent purchase, renewal, and actual model, hosting, and support costs would answer it. A cohort that demonstrates this pattern on representative workloads would move the action to Reach out.
