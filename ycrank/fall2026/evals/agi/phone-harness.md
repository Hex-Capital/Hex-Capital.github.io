# Phone Harness -- AGI Evaluation

**Action:** Watch  
**Evidence confidence:** Low

### Company case

The industry-enabled path is recurring native-app work that still requires a person to pick up a phone when a browser agent reaches a mobile-only step. Phone Harness describes an interface that lets a vision-capable agent read the screen and send inputs to personal or hosted phones. The seed-stage hypothesis is that developer teams could run permitted workflows at a cadence where staffing every run would be too costly. Under model parity, a hosted phone with persistent app sessions still supplies device access and state. The memo leaves the cost per successful run and the previously unaffordable cadence unverified. (The Idea, Defensibility, Key Risks)

The building-block path scores zero. Real phones are an input for agents executing native-app steps, but the memo offers no evidence that growing AI demand is straining phone supply or that equivalent capacity is slow to add. It identifies several existing device-access options. (The Idea, Market & Traction)

The shipped open-source harness and cloud beta support execution credit. The reported 5.1K stars and 522 forks show developer interest, while paid or repeat buyer use remains unverified. Posted cloud prices establish the offer, with device utilization, support, and failure costs still unknown. Those gaps limit confidence in demand and scale economics. (Market & Traction, Key Facts)

### Countercase

Phone Harness may save labor on workflows teams already find economical. The MIT-licensed local harness and competing hosted fleets give teams alternatives, while Apple Mirroring dependency and third-party app rules narrow the workflows Phone Harness can serve. Persistent app state may add switching costs, though repeat usage remains unverified. These facts limit durable value capture. The Pass gate would apply if the workflow proves to be a routine efficiency gain and neither AGI path remains supported. The specific manual handoff in browser-based workflows supports Watch at seed. (The Idea, Defensibility, Market & Traction, Key Risks)

### Decisive diligence question

Will a buyer pay to keep a permitted native-app workflow running at a cadence it previously could not afford with manual phone work? A paid pilot that sustains that cadence, measures cost per successful run against the manual baseline including device time, model usage, retries, and human intervention, and converts to repeat paid use would move the action to Reach out. Evidence that the buyer could already afford the target cadence and gained only routine labor savings would move it to Pass.
