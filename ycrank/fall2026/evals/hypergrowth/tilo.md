# Tilo -- Hypergrowth Evaluation

**Action:** Watch  
**Evidence confidence:** Low

### Company case

**Path A, product-led adoption,** is Tilo’s strongest path. The initial buyer would be an engineering team running recurring AI-agent workflows across several apps. Tilo’s browser demo, open-source local deployment, and Rust SDK give that team a route to try the product and build integrations. The memo describes shared app state, typed actions, and workspace-level history and permissions implemented in the public repository. Those features could give a team a reason to move a workflow onto Tilo if people and agents need to edit the same records and trace or undo changes. The memo documents a route to trial. Paid activation and repeat use remain unverified. (The Idea, Defensibility, Key Facts)

**Scenario assumption:** If Tilo charges for hosted workspaces, a team could try one workflow through the demo, pay to keep it running, and add workloads that reuse the same integrations. The same route could work in a second geography if buyers use apps Tilo already supports and can use the same hosting setup. Each additional workload would incur compute and storage costs. Each new account could add onboarding and support, and gaps in local app coverage or hosting requirements could add integration or rollout work. Tilo reports running 50 agents in one laptop workspace at about 60 MB per agent. That test gives a memory datapoint, while hosted contribution still depends on price and the full cost of serving a paying account. (The Idea, Market & Traction, Key Risks)

### Countercase

The strongest countercase is that Tilo’s advantage is easiest to demonstrate inside its native apps, while buyers’ important workflows may depend on third-party or Windows apps. If each new customer needs custom typed actions and help moving a workflow onto an early-alpha desktop, integration and support could grow with each sale. Tilo’s reported same-model speed and cost gains come from one task where the comparison failed, so the figures cannot establish savings across successfully completed workflows. The memo documents no customer rollout that establishes a structural ceiling on reach or contribution. The Pass gate remains unmet. (The Idea, Defensibility, Market & Traction, Key Risks)

### Decisive diligence question

Can an independent engineering team outside the US go from the browser demo to paying for a recurring multi-app workflow using existing integrations with little founder help? A paid deployment that runs again at the buyer’s normal cadence, with onboarding time and hosting cost recorded, would move the action to **Reach out**. Demo interest or a founder-built pilot would keep it at **Watch**.
