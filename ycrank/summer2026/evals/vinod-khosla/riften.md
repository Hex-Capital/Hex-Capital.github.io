# Riften -- Vinod Khosla Evaluation

The consequential version of Riften is not a cheaper API gateway. It is an infrastructure layer through which every company converts production experience into specialized models, collapsing dependence on expensive frontier inference. The demand pool is real: AI inference represented an estimated $106.15 billion in 2025 and is projected to reach $254.98 billion by 2030. But Riften does not quantify what fraction it can eliminate, how many workloads can migrate, or whether savings are 20% or 20x. A large cost pool is not yet a large consequence.

The technical thesis has two parts. Routing each request to the cheapest satisfactory model is replicable and already offered by Not Diamond, Martian, Unify, OpenRouter, and more than 16 methods in the open-source LLMRouter framework. The more interesting claim is that production outcomes train private open-weight models which progressively earn traffic from frontier models. That could create an application-specific learning loop rather than another interface wrapper. But Riften supplies no held-out benchmark, routing threshold, trained model, or evidence that its outcome signals are sufficient to reproduce task quality. Worse, unified evaluations found that several recent routers could not reliably beat a simple baseline. Today the claimed discontinuity is a hypothesis, not an auditable 5–10x result.

The economics are equally unfinished. Replacing frontier calls with smaller private models could produce attractive gross margins for customers, but no pricing, training cost, serving utilization, quality-adjusted cost, or migration curve is disclosed. The one-environment-variable integration lowers adoption friction; it does not prove parity. OpenRouter has raised $153 million and already operates a large model marketplace, while Not Diamond trains custom routers from customer evaluation data. Riften must therefore demonstrate that private-model progression compounds faster than competitors’ routing data and model access. Otherwise economic gravity makes this a thin gateway between customers and suppliers with greater scale.

The strongest bull case is that the gateway is merely the wedge. Normal usage could generate proprietary request, outcome, escalation, and acceptance data; DeepSeek-R1 and subsequent open-weight models provide increasingly capable substrates; each customer could then acquire a private model that is cheaper, better controlled, and harder to displace. This pattern fits my preference for scarce workflows becoming repeatable production systems. It also resembles the known exception where an initially modest product gains access to a giant existing value pool and evolves into infrastructure. The material difference is evidence: Riften has no reported customer, repeat usage, proprietary dataset, founder record, or working private model demonstrating that evolution.

Capital should first attack the kill risk: can production feedback train a smaller model that preserves application outcomes while materially reducing cost? The dossier identifies routing accuracy, adversarial steering toward expensive models, and sensitive-data handling, but Riften publishes no experiment, numerical pass threshold, budget, or stop condition for any of them. Founder identities and backgrounds are also unavailable, so there is no evidence of belief revision, complementary recruiting, or domain authority. These are not automatic pre-seed failures; they receive the appropriate missing-evidence priors. They do mean I cannot invoke an exceptional founder override.

My 36-month base case is that Riften either pivots into evaluation and observability infrastructure or remains a sub-$3 million ARR routing gateway, because routing commoditizes before private-model learning is proven. I pass today. One result flips the decision: a blinded benchmark on a named customer’s held-out production traffic showing that a Riften-trained private model sustains equivalent task acceptance at no more than 20% of frontier-model cost for 90 days. That would convert a fashionable architecture into a measurable cost discontinuity.
