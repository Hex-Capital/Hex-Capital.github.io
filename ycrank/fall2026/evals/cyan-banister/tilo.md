# Tilo -- Cyan Banister Evaluation

In 2032, I can imagine handing a computer a task, watching it work beside me, and reversing its mistakes without reconstructing what happened from screenshots. Tilo’s shared workspace, history, and undo are a small artifact from that world. Getting there requires applications to expose meaningful operations and people to trust delegated changes. The published framework makes that path concrete, but application migration and trustworthy delegation remain unfinished transitions. This is a plausible future with some machinery already built.

Why should an agent have to look at a button? Tilo identifies a real institutional failure in software: useful operations sit behind interfaces designed for human eyes and hands, making automation repeatedly interpret their appearance. Removing that translation could return time and control to users. But the dossier does not quantify the resulting economic burden reliably. The claim of up to 10,000× cheaper computer use has no independently reproduced benchmark. More consequentially, Browser Use structures existing websites, while Simular operates existing interfaces. Tilo must save enough effort to justify developers adopting its application model. A faster action is valuable; persuading someone to rebuild an application around it is a different transaction.

Quinten Wolff’s patent-workflow automation at BDPE during 2025–2026 matters more to me than either founder’s early admission to TUM. He has encountered real work that software must complete, and his public PineTime firmware project supplies another concrete building artifact. Xaver Emmerling began programming at twelve, but the dossier supplies little dated evidence of what he built before Tilo. There is relevant technical context here, with some evidence of independent curiosity. I cannot yet connect it into a long obsession with this particular problem, or assume that their shared BDPE affiliations mean Tilo grew directly from an operating wound.

The strongest argument for writing a check is the position underneath the visible agent wave. Tilo controls an implementation of the resource-and-action framework that could support many applications; this is more substantial than attaching a conversational interface to somebody else’s model. It fits my pattern of looking for concealed infrastructure. Yet the dependency is still prospective: no external developer population is shown to require Tilo. MIT licensing for the application framework and AGPL-3.0 elsewhere could help distribution, while leaving defensibility dependent on execution and ecosystem adoption. Three stars on a GitHub mirror tell me almost nothing about either. The missing signal is someone repeatedly doing costly work through this architecture because returning to the old way feels worse.

Permissions make the future credible or break it. Scoped grants and signed changes are affirmative architectural work, but unsettled offline revocation and unimplemented hosted-operator isolation leave important custody boundaries unresolved. I would not call this a demonstrated severe privacy violation; I also would not treat documented intentions as completed protection. The October 21 catalogue authorization expiry, which removed access across devices, exposes another source of dependency the team must manage. Their renewal procedures and monitoring response show attention to operating complexity. My prototype-led exceptions to missing revenue apply only partway here: Tilo has technical substance, but the dossier offers neither signed customer commitments nor the unusually deep founder history that would carry the remaining uncertainty.

I am neutral at **54/100**. No revenue is perfectly ordinary at this stage; absence of observed user behavior leaves this particular architectural bet untested. My flip condition is one independently observed, thirty-day external deployment in which a team repeatedly entrusts real work to Tilo with permission revocation demonstrated to work. That would establish something the public SDK cannot: people will accept a new application environment to gain dependable agency over their computers.
