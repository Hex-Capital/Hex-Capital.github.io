# Egoist Machines -- Paul Graham Evaluation

I start with what is missing: the dossier never names a moment when Egoist Machines was blocked and the founders bent the system to keep moving. Opening a waitlist on July 13, joining YC, publishing privacy terms, and announcing a later-summer launch show motion. They do not show resourcefulness under resistance. There is no rejected integration, failed prototype, security incident, or reluctant user followed by a shipped workaround. Since founder behavior is the controlling test, this absence is decisive.

David Khachaturov is plainly capable of building things. He has a Cambridge computer-science PhD, worked on OpenAI’s PaperBench and AI security at FrontierOne, and built a separate open-source project with 4,700 GitHub stars. But AI Passport is still described as an architecture: field-level requests, revocable access, approval, and receipts. The dossier supplies no live third-party integration, measured security result, working cross-application demonstration, or users successfully transporting context. Credentials and a good specification are not a technical proof.

The demand evidence is weaker. Erin McGurk has reached more than one million followers across platforms, which gives the team an unusually large pipe for consumer recruitment. Yet Egoist Machines has only 268 company LinkedIn followers, an unquantified waitlist, and no disclosed active users or repeat usage. “People who use several AI apps” is a category, not a narrow well. Office visits, university visits, and free bagels could become useful manual recruitment, but press coverage and a launch announcement are not evidence that anyone wants the crude product back after trying it.

The strongest part is the schlep. A user-owned permissions layer for health data, identity, preferences, and OAuth credentials forces the founders into security, consent design, application integrations, revocation, and audit receipts. Khachaturov’s security work is relevant, and McGurk’s consumer reach may help explain these abstractions to ordinary users. But the origin story is still that the founders formed the company around “shared concerns,” not that either repeatedly suffered this problem and built a tool for personal use. The dossier also shows no product revision caused by evidence, so I cannot tell whether they will behave like running backs when application developers or consumers reject the first workflow.

The bull case is sharp. This is a technical founder paired with a founder who already owns distribution, building a programmable interface for an emerging class of autonomous software. User-controlled memory could become a valuable standard if applications adopt it before native platforms close the gap. But that possibility collides with two red flags. Distribution depends on unspecified developers requesting and honoring passes, while OpenAI and Anthropic control the platforms and can reproduce portability controls. The consumer product is promised free for life, with no published developer pricing, so the path from adoption to an equity-scale business is also unproved. The exception test fails: there is neither unmistakable user pull nor independently validated technical proof strong enough to replace the failed founder-action gate.

I would pass today. Within 36 months, I expect Egoist Machines either to pivot from a consumer passport into a developer-facing consent and memory SDK or to become inactive; the security and integration work is more concrete than the demonstrated consumer need. One condition would flip my decision: after a named platform or integration refusal, the founders ship a workaround that lets at least 100 users move context weekly across three independent applications for eight consecutive weeks.
