# Tilo -- Naval Ravikant Evaluation

Tilo’s founders have earned the right to attempt this. Quinten Wolff built patent-workflow automation at BDPE during 2025–2026; the team has now published an application framework with typed actions, shared state, permissions, and undo. That is specific knowledge expressed through work. TUM early admission adds little to my decision. Building systems that encounter actual workflow constraints adds considerably more. The remaining uncertainty is whether their learning produces something other developers need enough to adopt.

The central investment problem is what survives replication. Tilo licenses its application framework under MIT and other code under AGPL-3.0. Open source can attract contributors, but the license does not establish an exclusive asset. A competitor could reproduce the architecture without inheriting customers—because the dossier establishes no customer network to inherit. Shared state makes applications cooperate inside a workspace; it does not, by itself, make one customer more valuable to another. The defensibility evidence is weaker than mere silence: the implementation is explicitly reusable, while the proposed ecosystem remains hypothetical.

The strongest argument for investing is architectural. Screenshot-and-click agents operate through an interface built for human eyes. Typed actions could remove that translation cost, and a common model for permissions, history, and undo could become useful infrastructure across many applications. Tilo fits my pattern of tools that let individuals turn knowledge into scalable output, and its public SDK permits outsiders to build. I can invest before revenue or a distribution loop exists when a strange prototype demonstrates exceptional product insight. Here, however, the benefit depends on developers integrating native actions; conventional Linux applications receive fewer capabilities. Browser Use and Simular offer routes through existing software. Tilo must persuade developers that deeper integration earns enough advantage to justify the work. The claimed cost reduction of up to 10,000 times has no independently reproduced benchmark.

There is room beyond the first wedge: developers deploying computer-use agents could lead into shared human-agent workspaces and enterprise workflow infrastructure. The same action-and-resource model supplies a plausible bridge. But the cited $16.7 billion AI operating-system market includes mobile and embedded deployments, so it cannot establish Tilo’s reachable opportunity. Nor do three stars on a GitHub mirror establish developer rejection; they simply provide no evidence of a contribution loop. With no disclosed payer, pricing, or revenue, direct value capture remains unknown. I assign the missing-evidence defaults to both the user loop and monetization.

The documented October 21 catalogue expiry and the team’s published response suggest willingness to expose operational problems. I see no documented integrity violation or financing-pressure red flag. Nevertheless, unresolved revocation boundaries and unimplemented hosted-operator isolation matter when the product promises agents shared access to consequential work. My money would stay out today: demonstrated building ability is carrying almost the entire investment case. One verifiable condition would reopen it—an independently documented deployment where unrelated developers’ applications work together through Tilo’s shared action model and users repeatedly adopt those applications because of that interoperability. That would show the beginnings of value accumulating beyond the founders’ own code.
